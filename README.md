# git-petri

Чашка Петри для ваших git-хостингов в терминале. Репозитории одной организации
лежат одной кучей, от репозиториев отпочковываются ветки, PR/MR и коммиты.
Чем свежее активность, тем крупнее организм и тем дальше он отходит от родителя.
Размер репозитория зависит ещё и от объёма работы в нём: числа живых веток
(с коммитами за 30 дней) и открытых PR — считаются все, а не только нарисованные.

Поддерживаются GitHub (и GHES), GitLab, Gitea / Forgejo. Чистый Python ≥ 3.10,
без зависимостей. На Omarchy цвета берутся из текущей темы и меняются вместе с
ней, на остальных системах используется встроенная палитра.

## Установка

    ./install.sh              # в ~/.local, без root; PREFIX=/путь меняет место
    ./install.sh --uninstall  # удалить; аккаунты в ~/.config/git-petri остаются

На Omarchy установщик добавляет пункт «Git Petri» в системное меню (блок с
метками в `~/.config/omarchy/extensions/omarchy-menu.jsonc`, перед первой правкой
делается копия файла); `--uninstall` его убирает.

Нужен только `python3` ≥ 3.10 (Arch, Debian 12+, Ubuntu 22.04+); если его нет или
`~/.local/bin` не в `PATH`, скрипт подскажет команду. `xdg-open` нужен лишь для
открытия ссылок. Терминалу нужны truecolor и шрифт с символами Брайля.

## Запуск

    git-petri            # первый запуск спросит провайдера и токен; работает и `git petri`
    git-petri --demo     # синтетические данные, без сети и токена
    ./git-petri          # то же прямо из клона, без установки

Токену достаточно чтения:

| Провайдер | Права |
|-----------|-------|
| GitHub    | classic: `repo`, `read:org`; fine-grained: Metadata, Contents, Pull requests, Actions — read-only |
| GitLab    | `read_api` |
| Gitea     | `read:user`, `read:repository`, `read:organization` |

Аккаунты лежат в `~/.config/git-petri/config.json` (права 0600). Вместо самого
токена можно хранить команду, которая его печатает (`"token_cmd": "gh auth token"`,
`pass show …`) — тогда токен на диск не попадает.

    git-petri add | accounts | remove <имя>
    git-petri activity          # показать период активности
    git-petri activity 3d       # задать: 12h, 3d, 2w, 1m или default; запущенная чашка подхватит сама

## Что на чашке

| Организм | Вид |
|----------|-----|
| организация / владелец | своего тела нет: её репозитории лежат одной кучей, над кучей — тусклая подпись |
| репозиторий | колония; чем больше живых веток и PR, тем крупнее и ближе к середине кучи |
| ветка | бирюзовая клетка; коммиты — споры, свежие ближе и ярче |
| PR / MR | фиолетовый ромб, нить к своей ветке |
| CI | крупная клетка с мембраной: ✓ зелёная, жёлтая — идёт, ✗ красная; имя подписано только у упавших и идущих |

Упавший пайплайн остаётся красным (в том числе пока идёт перезапуск), пока тот же
workflow в той же ветке не пройдёт успешно — на этом же или новом коммите. Тогда
клетка зеленеет волной от центра. Отменённые и пропущенные запуски ничего не меняют.

Репозитории без пушей дольше `stale_days` (7 дней) на чашку не попадают, а
организации, где таких большинство, сжимаются до активной части или исчезают
совсем. Их число видно в шапке («N dormant»), клавиша `d` показывает их и прячет.

## Клавиши

`tab` / стрелки — выбрать организм, `o` / `enter` — открыть в браузере, `l` — подписи, `d` — спящие,
`r` — обновить сейчас, `esc` — снять выбор, `q` — выход. Мышь: клик по организму — выбрать, клик по ссылке в подсказке — открыть.

Чашка по умолчанию неподвижна: в покое процесс спит без таймеров и просыпается
только от клавиши, изменения размера окна или ответа опроса. Когда опрос приносит
изменения, колонии около полуминуты тягуче перетекают в новую раскладку и снова
замирают. Тикает только значок идущего пайплайна — раз в секунду.

Опрос идёт каждые `interval` секунд, пока что-то меняется или идёт пайплайн; если
ответы повторяются, интервал растягивается до `max_interval` (5 минут). Клавиша `r`
опрашивает сразу и возвращает частый режим. Смена темы Omarchy подхватывается при
следующем пробуждении.

В маленьком окне (четверть экрана) чашка сама убирает детали: сначала старые
зелёные пайплайны и лишние ветки, затем спутники неактивных репозиториев.
Непочиненные падения видны всегда.

## Настройки

Ключ `settings` в конфиге: `interval` (45 с), `max_interval` (300 с), `fps` (12, только пока чашка перестраивается), `max_repos` (60),
`active_repos` (12 — у скольких самых свежих репозиториев запрашиваются ветки, PR и CI),
`active_days`, `stale_days`, `branches`, `commits`, `pulls`, `runs`.
