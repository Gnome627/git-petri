# git-petri

Чашка Петри для ваших git-хостингов в терминале. Организации — крупные колонии,
от них отпочковываются репозитории, от репозиториев — ветки, PR/MR и коммиты.
Чем свежее активность, тем крупнее организм и тем дальше он отходит от родителя;
заброшенное остаётся вросшим в организацию.

Поддерживаются GitHub (и GHES), GitLab, Gitea / Forgejo. Чистый Python ≥ 3.11,
без зависимостей. Цвета берутся из текущей темы omarchy и меняются вместе с ней.

## Запуск

    ./git-petri            # первый запуск спросит провайдера и токен
    ./git-petri --demo     # синтетические данные, без сети и токена
    ln -s "$PWD/git-petri" ~/.local/bin/   # после этого работает и `git petri`

Токену достаточно чтения:

| Провайдер | Права |
|-----------|-------|
| GitHub    | classic: `repo`, `read:org`; fine-grained: Metadata, Contents, Pull requests, Actions — read-only |
| GitLab    | `read_api` |
| Gitea     | `read:user`, `read:repository`, `read:organization` |

Аккаунты лежат в `~/.config/git-petri/config.json` (права 0600). Вместо самого
токена можно хранить команду, которая его печатает (`"token_cmd": "gh auth token"`,
`pass show …`) — тогда токен на диск не попадает.

    git-petri add | accounts | remove <имя>

## Что на чашке

| Организм | Вид |
|----------|-----|
| организация / владелец | большая колония цвета акцента |
| репозиторий | колония поменьше, связана нитью с организацией |
| ветка | бирюзовая клетка; коммиты — споры, свежие ближе и ярче |
| PR / MR | фиолетовый ромб, нить к своей ветке |
| CI | крупная клетка с мембраной: ✓ зелёная, жёлтая — идёт, ✗ красная |

Упавший пайплайн остаётся красным (в том числе пока идёт перезапуск), пока тот же
workflow в той же ветке не пройдёт успешно — на этом же или новом коммите. Тогда
клетка зеленеет волной от центра. Отменённые и пропущенные запуски ничего не меняют.

## Клавиши

`tab` / стрелки — выбрать организм, `o` / `enter` — открыть в браузере, `l` — подписи,
`r` — обновить сейчас, `esc` — снять выбор, `q` — выход. Мышь: клик по организму.

Чашка по умолчанию неподвижна: в покое ничего не считается и не рисуется (доли
процента CPU). Когда опрос приносит изменения, колонии около полуминуты тягуче
перетекают в новую раскладку и снова замирают. Постоянно тикает только значок
идущего пайплайна — два раза в секунду.

В маленьком окне (четверть экрана) чашка сама убирает детали: сначала старые
зелёные пайплайны и лишние ветки, затем спутники неактивных репозиториев.
Непочиненные падения видны всегда.

## Настройки

Ключ `settings` в конфиге: `interval` (45 с), `fps` (12, только пока чашка перестраивается), `max_repos` (60),
`active_repos` (12 — у скольких самых свежих репозиториев запрашиваются ветки, PR и CI),
`active_days`, `branches`, `commits`, `pulls`, `runs`.

    python3 -m unittest discover -s tests
